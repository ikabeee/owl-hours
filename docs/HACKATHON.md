## Event requirements

- Build period: **October 27–November 4, 2026**.
- At most **four participants** per team; solo entries are allowed.
- Submit **one project per team**, through one appointed representative.
- Choose a competition track: **Indie Developer or Startups — team decision TBD**.
- Address either *Build for Your World* (a domain problem) or *Push the Frontier*
  (a new technical capability). Our problem statement and MVP remain TBD.
- Meaningfully use **Meta Model API and/or Meta open-weight models**.
  Using every listed model is not required; model choice and integration are TBD.
- The repository must be **public**. The submission must include an accessible
  **three-minute demo video**, and judges also evaluate the code and live product.
- Clearly identify work created during the event. If existing code or a product
  is reused, distinguish it from the new contributions; the demo should highlight
  only the features and functionality built during the hackathon.
- Use only code, data, and assets we have rights to use, and follow applicable
  legal, ethical, and platform rules.
- Avoid the guide's anti-project examples, including **basic RAG applications**
  and **simple image analyzers**. Review the complete guide before locking scope.

The supplied guide's judging-rubric table was unavailable, so no scoring weights
are reproduced here.
